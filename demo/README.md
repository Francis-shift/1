# 画像驱动个性化反馈 · 第一版 demo

验证目标:**同一个错误,在不同学习者画像下产生不同反馈** —— 证明"画像"这个
变量真的能改变系统的反馈方式。第一版**不接 VS Code、不接真实数据**,用最小
代价先把"用户特征 → 触发辅助策略 → 给出具体帮助"这条链路跑起来。

## 快速运行

```bash
python3 demo/demo.py           # 3 个错误案例 × 3 份画像 的反馈对照矩阵
python3 demo/demo.py --check   # 先核验错误案例确实会失败,再生成反馈
python3 demo/run_case_check.py # 只核验:参考程序全过、3 个错误案例复现失败
```
纯标准库,无需安装依赖。学生程序在独立子进程中带超时执行,安全。

## 设计要点(为什么这样拆)

1. **诊断层 vs 画像层分离**:错误"改什么"由诊断包客观给出(对所有人相同);
   "怎么对这个人讲"由画像层决定(因人而异)。这正是本项目相对 BRAFAR 的增量。
2. **画像 → 风格的四个旋钮**:解释粒度 / 代码供给 / 引导强度 / 语言风格。
   6 条规则把画像特征(K/D/H/E)映射到这四个旋钮,再由模板落成话术。
3. **可替换插槽**:黄新意的部分全部集中在一个文件、以数据+函数形式暴露,
   方便迭代;房年朗的骨架不需要因画像调整而改动。

## 已知边界(留给下一版)

- 诊断包目前是**预先整理**的(第一版);正式版把 `demo.py: make_diag()` 换成
  实时调用 BRAFAR 工具产出 fault_line / patched。
- 画像是**手工模拟**的;后续替换为从真实行为数据(Refactory/CS1QA 等)算出的画像。
- 反馈用**模板**生成;后续可把诊断包 + 画像 + 风格拼进提示词,交 LLM 生成更自然的话术。
